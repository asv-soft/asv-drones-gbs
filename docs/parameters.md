# MAVLink board parameters

## Source and generation lifecycle

The parameter definition pipeline is:

```text
JsonParams/board.params.json
          |
          | read by
          v
JsonParams/MavParams.tt (T4 template)
          |
          | executed by T4.Build during the contracts build
          v
JsonParams/MavParams.cs (generated C#)
          |
          v
IMavParamsSource / MavParams.Instance -> MAVLink parameter server
```

All paths are relative to `src/Asv.Drones.Gbs.Contracts/`. The contracts
project declares `MavParams.tt` as the generator for `MavParams.cs` and carries
the `T4.Build` package that runs the template in build environments.

`board.params.json` is the source of truth for parameter names, MAVLink types,
descriptions, units, ranges, defaults, increments, categories, groups,
enumerated values, and persistence flags. `MavParams.tt` owns the transformation
and supported JSON-to-.NET/MAVLink type mapping.

`MavParams.cs` starts with an `AUTOGENERATED PARAMS` / `Do not edit manually`
warning. Never edit that file directly. A direct change can be overwritten on
the next generation and creates a mismatch between shipped metadata and its
source.

## Change workflow

1. Edit `JsonParams/board.params.json` for metadata changes, or
   `JsonParams/MavParams.tt` for generator behavior.
2. Build the contracts project from the repository root:

   ```bash
   dotnet build src/Asv.Drones.Gbs.Contracts/Asv.Drones.Gbs.Contracts.csproj
   ```

3. Review the diff in both the source input and generated output:

   ```bash
   git diff -- src/Asv.Drones.Gbs.Contracts/JsonParams
   ```

4. Run the contracts tests and the full solution build before committing:

   ```bash
   dotnet test src/Asv.Drones.Gbs.Tests/Asv.Drones.Gbs.Tests.csproj
   dotnet build src/Asv.Drones.Gbs.sln --configuration Release
   ```

The generated output is tracked so consumers and reviewers can see the exact
metadata compiled into the package. Source and output changes belong in the
same commit.

## Hand-written companion files

- `IMavParamsSource.cs` defines the enumerable parameter contract consumed by
  the runtime.
- `MavParams.Static.cs` is a hand-written partial class for stable group/category
  constants and filtering helpers.
- `MavParams.cs` is the generated partial class with descriptors and the ordered
  `Params` enumeration.

Hand-written behavior must stay outside the generated file, normally in another
`MavParams.*.cs` partial-class file.

## Ownership and consumers

| Artifact | Owner | Consumers |
| --- | --- | --- |
| `board.params.json` | Contracts/package maintainers | T4 template, metadata tests, documentation checks |
| `MavParams.tt` | Contracts/package maintainers | T4.Build |
| `MavParams.cs` | Generator only | Contracts assembly and all static descriptor users |
| `MavParams.Static.cs` | Contracts/package maintainers | Code that filters or categorizes descriptors |
| `IMavParamsSource` | Contracts API maintainers | `MavlinkServer` through DI |

`Program.cs` passes `MavParams.Instance` to `AddMavlinkServer()`. Consequently,
all seven descriptors are exposed by the persistent MAVLink parameter server,
even when no service code reads a descriptor directly.

| Parameter | Type / range / default | Direct runtime consumer and effect |
| --- | --- | --- |
| `BRD_SYS_ID` | `Int32`, 0–255, default 1 | `MavlinkServer` reads the persisted value when constructing `MavlinkIdentity.SystemId` |
| `BRD_COM_ID` | `Int32`, 0–255, default 254 | `MavlinkServer` reads the persisted value when constructing `MavlinkIdentity.ComponentId` |
| `BRD_SERIAL_NUM` | `Int32`, 0–9,999,999, default 13 | No direct consumer in this repository; available to MAVLink parameter clients as board identity metadata |
| `BRD_REBOOT_CMD` | `Int32`, 0–1, default 0 | `SystemControlHandler` maps a remote command update to OS reboot |
| `BRD_SHUTDOWN_CMD` | `Int32`, 0–1, default 0 | `SystemControlHandler` maps a remote command update to OS shutdown |
| `BRD_RESTART_CMD` | `Int32`, 0–1, default 0 | `SystemControlHandler` maps a remote command update to service/process restart |
| `BRD_V2EXT_ON` | `Int32`, 0–1, default 1 | `MavlinkServer` decides at construction time whether to register MAVLink v2 extension wrapping |

The command descriptors are handled through `Params.OnInt32Command(...)`, not
ordinary polling. Identity and wrapping values are read only while the
singleton `MavlinkServer` is created; changing them in persistent configuration
does not reconstruct the server in the running process.
